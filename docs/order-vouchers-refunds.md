# 订单示例、票券核验与会员退款

## 小程序订单列表与独立详情

- 列表不再展示订单号、票券号或逐票编号，只展示商品摘要、日期、状态、金额与操作入口。
- “查看详情”跳转 `/pages/orders/detail?id={真实订单ID}`。服务端订单列表返回 `id`，
  详情接口 `GET /api/v1/orders/{id}` 同时兼容原订单号查询，继续执行订单访问权限检查。
- 详情页完整展示订单号，门票逐张展示所有票券及状态，每个编号独立调用
  `uni.setClipboardData` 复制。无票券的公共票/储值订单不出现空白凭证区域。
- 私汤展示真实预约编号、已签发的私汤票券号、日期与时间；房型字段不存在时不编造。
- 实付金额来自成功支付记录；储值到账金额来自实际充值账本，无记录时显示待确认。
- 列表与详情页复用现有退款资格校验及会员退款申请接口。未新增取消订单规则或接口；
  客服沿用前台/园区公示电话提示。
- 原分类与读取上限保留；原系统没有独立分页流程，本次不增加或修改分页业务。

## 订单示例

小程序开发环境的订单页提供“查看 8 组示例订单”。示例与真实订单分开展示，
不会调用真实支付、核销或退款接口，也不写入业务数据库。

| 类型 | 状态 | 订单号 | 票券号 | 申请退款 |
| --- | --- | --- | --- | --- |
| 公共票 | 待付款 | 有 | 无 | 否 |
| 公共票 | 待使用 | 有 | 每张票独立编号 | 是，须全部未使用 |
| 公共票 | 已完成 | 有 | 保留已核销编号 | 否 |
| 私汤 | 待付款 | 有 | 无 | 否 |
| 私汤 | 待使用 | 有 | 独立私汤编号 | 是 |
| 私汤 | 已完成 | 有 | 保留已核销编号 | 否 |
| 储值 | 待付款 | 有 | 无 | 否 |
| 储值 | 已完成 | 有 | 无 | 否 |

公共票部分使用时仍显示待使用，但不可申请整单退款。
私汤“已完成”表示票券已核销；房间使用中、结束、清洁由原房态流程管理。

## 真实票券与前台

- 公共票成功支付后服务端逐人签发票券。前台在“票券核验”输入真实票券号或订单号。
- 私汤成功支付且预约确认后返回 `ticket_no=PV-{booking_id}`；该编号与预约唯一对应，
  不改写预约主键。前台在“私汤核验与房态”输入该编号、原订单号或预约编号。
- 首次核验成功。新的核验请求再次使用相同票券返回 409；相同请求 ID 的网络重试
  返回原结果，避免因网络超时重复扣票或分房。重复核验不能再次开始计时。
- 普通会员无权调用前台核验接口。测试中的前台身份仅用于隔离测试库。
- `DEMO-`/`EXAMPLE-` 编号仅供样式预览，不能拿到真实前台核销。

### 同订单多张公共票统一核销

前台“票券核验”输入任意一张真实票券号或订单号，先点击“查询所属订单”。
页面展示该订单的全部票券，默认不勾选。可逐张勾选或全选当前可核销票券，
核对订单号、人数及所选票面金额后点击“确认核销已选 N 张”。

- 只允许同一公共票订单内的票券，不检索或连带核销会员的其他订单。
- 已使用、失效、未付款、退款审核中的票券不可勾选。后端仍会重新检查。
- `POST /api/v1/operations/tickets/admit-batch` 接受 `order_no`、`ticket_nos`、
  `request_id`、`reason`。最多 40 张，不允许重复号码。
- 一笔数据库事务处理整批：任何一张校验失败，整批不核销。
- 相同请求 ID 和相同订单/票券集合的重试返回原结果；改变集合会拒绝。
- 网络失败时前端保留本批请求 ID，避免超时重试重复核销；失败不代表可直接放行。
- 成功后刷新票券状态、剩余数量并记录本批明细。私汤仍使用原核验分房入口。
- 迁移 `e3f4a5b6c7d8` 新增批次幂等记录表，不改变单张核销接口。

## 会员退款申请

1. 会员提交 `POST /api/v1/orders/{order_no}/refund-application`，填写原因。
2. 仅本人已支付、全部未使用的公共票或未核销的确认私汤允许申请整单退款。
3. `PENDING` 期间暂停票券核销及私汤分房，不释放房间库存、不退钱。
4. 财务/管理员进入 Web“异常看板 → 会员退款申请审核”，填写审核意见。
5. 拒绝恢复核验资格；可修改原因重新申请。批准调用既有原支付来源退款服务。
6. 余额退款成功后才展示已退款；微信退款 `ACCEPTED` 仅表示受理，不能展示到账成功。
7. 相同审核重复提交不会重复退款。储值不提供退款申请。

接口：
- GET/POST `/api/v1/orders/{order_no}/refund-application`
- GET `/api/v1/operations/refund-applications`
- POST `/api/v1/operations/refund-applications/{order_no}/review`
