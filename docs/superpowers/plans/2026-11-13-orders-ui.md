# Orders UI implementation plan

Use the approved order mockup with the existing uni-app/Vue 3 architecture.
Keep native navigation/tabBar, shared authentication and backend APIs unchanged.

1. Add behavior tests for order presentation, category filtering, protected loads,
   bounded detail hydration, retry and stale-response protection. Observe failures.
2. Implement page-local `model.js` with reactive order state and presentation.
   Keep paid/payment status distinct from admission and booking status.
3. Replace only orders index.vue/style.css with ivory/teal/gold layout, three
   thumbnail types, native category buttons, status pills and expandable details.
   Handle guest, loading, empty, list errors and per-order detail errors explicitly.
4. Encode three source illustrations as compressed 320px JPEG thumbnails under
   src/static/orders. Retain originals in docs/design-assets/orders.
5. Run frontend_1 tests and mp-weixin build. Render the actual order SFC in an
   isolated headless browser harness, with mocked transport only, at 320/375/414px.
   Check long identifiers, large amounts, status widths and async detail behavior.
   Do not control the user's desktop or claim WeChat-tool runtime verification.
